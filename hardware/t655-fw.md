# t655-fw — HP Elite t655 Thin Client (firewall)

Status: **OPNsense 26.7.8_2 (FreeBSD 15.1-p6), WAN-only, GUI locked to Mint, monitored
by LibreNMS (device 6) since 2026-11-09.** Not routing anything yet. See SESSION-47.

## Role
Stateful firewall for the lab. Planned as router-on-a-stick: one cable to
SG300 **gi5** as an 802.1Q trunk, VLAN 20 first (Phase 1), VLAN 10 later
(Phase 3). Replaces the SG300's stateless ACLs where state matters.

Chosen over the t640 for this role: newer BIOS (2024) at the network edge and
4 cores for future Suricata. Its eMMC-style flash suits a box that barely writes.

## Gotchas
- **Never connect a fresh OPNsense to a production network with an interface
  set as LAN.** Default LAN = 192.168.1.1 + DHCP server = rogue DHCP.
- **"No LAN" isn't proof of no DHCP.** dnsmasq kept listening on `*:67` with
  leftover LAN ranges. Check `sockstat -4l | grep ':67 '` before plugging in.
- **The setup wizard reassigned `re0` back to LAN.** Recheck the console
  header (`WAN (re0)`) after the wizard and after every reboot.
- **Finishing the wizard re-enables the packet filter.** With no WAN pass rule
  you're locked out. Recovery: console shell → `pfctl -d`, add the rule, Apply,
  `pfctl -e`, reload to prove it.
- The console header is printed once at boot and isn't refreshed. A late DHCP
  lease won't show. Use `ifconfig re0 | grep "inet "` or log out and back in.
- Uncheck **Block private networks** and **Block bogon networks** on WAN —
  this WAN is 192.168.8.0/24.
- `os-realtek-re` is a **community** plugin — hidden until "Click to view the community plugins".
- **A rule does nothing until Apply.** Live View (Firewall → Log Files) shows blocks
  and which rule decided — check it first when a test fails.
- **Anti-lockout attaches to LAN; with no LAN it lands on WAN** and bypasses
  source-restricted GUI rules. Disable it once your own allow rule is proven.
- Confirm updates by the **version number** afterwards: the 10-30 update silently
  never finished (still 26.7, still 91 pending).
- LibreNMS needs **ICMP** as well as SNMP to add a device and track up/down.
- 26.x rule form: set **Interface (rule)** explicitly — `any` would also cover
  future interfaces (e.g. the lab VLAN).
