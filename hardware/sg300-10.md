## Specs
- 10 ports Gigabit Ethernet (gi1–gi10)
- Managed. **Running in Layer 3 (Router) mode since 2026-09-06.**
- Firmware: **SW version 1.1.2.0, dated 12-Nov-2011.** Very old. Documentation
  for newer SG300 firmware or mainline IOS often does NOT apply — always check
  the live command tree with `?`.
- **No DHCP server on this image.** `ip dhcp ?` offers only `information`,
  `relay`, `tftp-server`. VLAN 10/20 clients use static addressing.
- Web GUI + SSH/CLI management
- Firmware image note: this image does **NOT** support `write memory`.
  Save with `copy running-config startup-config`.

## Management
- Hostname: `sg300-apt`
- Management IP: **192.168.8.165/24 on VLAN 1** (DHCP from the Beryl)
- Gateway: 192.168.8.1
- In **Router mode**, multiple SVIs are supported and assigning an IP to
  another VLAN *adds* an interface. (In the old Layer 2 mode it MOVED
  management instead — an instant lockout. That risk is gone, but only
  because of the mode.)
- Default account: `cisco`, privilege 15. Custom GUI-created users don't work
  until the password is saved to startup-config.
- `enable` is unnecessary when the prompt already ends in `#`.
- Clock set manually, reports UTC, no NTP configured.

### SSH access (crypto workaround required)
Modern OpenSSH refuses this switch's key exchange algorithms by default
(`no matching key exchange method found`) — it only offers SHA1-based KEX.
Permanent fix on the Mint laptop, **scoped to this host only** so the
weakened crypto never applies to any other SSH target:
```
Host sg300
    HostName 192.168.8.165
    User cisco
    KexAlgorithms +diffie-hellman-group1-sha1,diffie-hellman-group-exchange-sha1
    HostKeyAlgorithms +ssh-rsa
    PubkeyAcceptedAlgorithms +ssh-rsa
    Ciphers +aes128-cbc,3des-cbc,aes256-cbc
```
Then simply: `ssh sg300`

SHA1 is weak — acceptable ONLY because this device is LAN-only and
unreachable from the internet. **Never reuse this Host block for the VPS.**

## VLANs / SVIs (Router mode)
| VLAN | SVI | Type | Role |
|---|---|---|---|
| 1 | 192.168.8.165/24 | DHCP from Beryl | management |
| 10 | 192.168.10.1/24 | Static | production (for pve-node1) |
| 20 | 192.168.20.1/24 | Static | lab / test |

`IP Forwarding: enabled` — the switch routes between these itself.

**Default route comes from DHCP, not a static route.** `show ip route` shows
`D 0.0.0.0/0 via 192.168.8.1`. Adding a static default fails with
`No such instance exists` because the slot is already occupied. This is
correct behaviour, not an error.

Empty VLANs do not appear as connected routes until a device is plugged into
a port in that VLAN.

**No DHCP service for VLAN 10/20** — clients are addressed statically.

### Required on the Beryl (return routing)
Without these, VLAN 10/20 clients reach the Beryl but get no replies from the
internet — classic asymmetric routing.
```
192.168.10.0/24 via 192.168.8.165
192.168.20.0/24 via 192.168.8.165
```
Verify in the kernel table, not just the LuCI form: `ip route | grep 192.168`

### ACL policy on VLAN 20 (added 2026-09-20)

`vlan20-policy` — an extended ACL enforcing isolation as explicit policy
rather than relying on absence of routing.

```
ip access-list extended vlan20-policy
 deny ip any 192.168.10.0 0.0.0.255     # VLAN 10 (production)
 deny ip any 192.168.8.165 0.0.0.0      # the switch's own management IP
 deny ip any 192.168.8.0 0.0.0.255      # rest of VLAN 1
 permit ip any any                      # internet
```

**Bound to the PHYSICAL PORT, not the VLAN interface:**
```
interface gigabitethernet3
 service-acl input vlan20-policy
```

`service-acl` does **not** exist on `interface vlan X` on this firmware —
only on physical ports, and only in the `input` direction. gi3 is the VLAN 20
access port, so all VLAN 20 traffic enters there; same effect.

Verified by function 2026-09-20, from a VLAN 20 client with WiFi off:

| Destination | Result |
|---|---|
| 192.168.20.1 (own gateway) | 0% loss — allowed |
| 192.168.10.1 (VLAN 10) | 100% loss — denied |
| 192.168.8.165 (switch mgmt) | 100% loss — denied |
| 192.168.8.1 (Beryl) | 100% loss — denied |
| 1.1.1.1 (internet) | 0% loss, ttl=57 — allowed |

Same ping to .8.165 returns 0% loss from VLAN 1 — the ACL is scoped to gi3
only.

> **Wildcard masks, not subnet masks.** `1=wildcard (ignore), 0=hit (must
> match)`. A whole /24 is `0.0.0.255`. A single host is `0.0.0.0`.

### Verified end to end 2026-09-07
From a VLAN 20 client on gi3 (WiFi off), TTL shows the routing hop:
```
192.168.20.1   ttl=64    own SVI
192.168.8.165  ttl=64    switch management
192.168.8.1    ttl=63    <-- decremented crossing the SG300
1.1.1.1        ttl=57    internet
```

## Gotchas & lessons
- `write memory` does NOT exist on this image → `copy running-config startup-config`.
- Mid-paste `Cold Startup` output means a reboot risk with unsaved config.
- Don't paste a whole config block while already inside `(config)` mode.
- `clock set` takes its arguments literally — `clock set 11:42:00 1 Sep 2026`,
  not a placeholder format string.
- **Answering `Y` to "apply this new configuration?" when adding an IP to a
  non-management VLAN = instant lockout.** The prompt defaults to `[N]` for
  a reason.
- Turn WiFi OFF (`nmcli radio wifi off`) before any VLAN isolation test, or
  the laptop stays reachable over the old path and the test silently lies.
  Prove it with `ip route get <target>` — don't assume.
- **`set system mode router|switch` is typed at the `#` prompt, NOT inside
  `configure terminal`.** In config mode `set` is unrecognized.
- **A mode change wipes startup-config and reboots — in BOTH directions.**
  Going L3 → L2 later is a second full rebuild, not an undo.
- **After a reset, SSH is off.** Port 22 refuses connections. The web GUI at
  `http://192.168.8.165` is still enabled by default — recover through it and
  re-enable `ip ssh server`.
- Factory fallback address if DHCP fails after a reset: **192.168.1.254/24**.
- Passwords can't be reused after a wipe: `password cannot repeat current`.
- An unconfigured port reports `Port Mode: Trunk` by default. Read the VLAN
  membership table, not the mode label.
- **`service-acl` exists on physical ports only**, not on `interface vlan X`.
  Only the `input` direction is supported.
- **`copy runnning-config`** (three n's) fails with "The source
  file/directory does not exist" — it's a typo, not a broken command.
