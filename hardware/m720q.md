## Build log — gotchas & lessons
- `dmidecode` is the source of truth for RAM, not eyeballing photos → confirmed 2×8, both slots full.
- NO-CARRIER with a known-good cable = dead port, not your gear → the apartment jack is dead.
- On managed/shared WiFi you don't control, bring your own router (Beryl AX, repeater mode) to get a private LAN devices can actually talk on.
- A static-IP device won't show in the router's DHCP client list — "not in the list" ≠ "not connected"; test the IP directly.
- USB flash must fully complete (including the sudo password prompt) or the installer boots garbage; remove the USB after install to stop PXE boot loops.
- Fresh Proxmox defaults to PAID enterprise repos (401s) → switch to no-subscription. The download.proxmox.com SSL mismatch is fixed by using `http://` (repos are GPG-signed, so transport TLS isn't needed).
- Correct keyring filename is `proxmox-archive-keyring.gpg` (singular). Heredoc pastes in the web shell get mangled — always `cat` to verify before `apt update`.
- First reboot after a big upgrade is slow (network comes up last) — give it 2–3 minutes before assuming it's broken.
- `dmesg -T` FIRST for anything hardware-adjacent. `LOWER_UP` means carrier detected, NOT that traffic passes — and "reseating fixed it" doesn't prove a physical fault (a link reset also clears a driver stall). This is what hid the e1000e bug for a week.
- On a VM, TRIM is what shrinks backups — deleting files alone does nothing (`fstrim -av`).
- Recreate exact usernames/UIDs so an app's hardcoded /home paths just work (used for both OpenClaw's `ubuntu` and Hermes's ec2-user/asl-app/hermes-asl).
- Verify a service by FUNCTION (send a message, get a reply), not by "service running" — and a reboot is the real durability test for a user service + lingering.
- KVM reserves a VM's full configured RAM at boot regardless of actual guest usage — a host showing tight "free" memory doesn't necessarily mean real pressure; check inside each guest before concluding more RAM is needed.
